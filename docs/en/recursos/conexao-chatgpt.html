Connect ChatGPT

Configure ChatGPT with Moodle MCP using the visual OAuth setup guide, including the optional PNG icon, server URL and client registration.

How it works

Install local_mcp under local/mcp, complete the Moodle plugin upgrade and open Site administration → Local plugins → Moodle MCP → Connections. This page provides a visual guide to configuring ChatGPT with OAuth, including the values needed when registering the MCP server.

In ChatGPT, add a custom MCP server with the URL https://YOUR-MOODLE/local/mcp/server.php. Choose OAuth authentication and dynamic client registration (DCR). You can also use the optional PNG icon shown in the guide to identify the integration.

Sign in through Moodle and authorize mcp:read for queries and, when needed, mcp:write for administrative operations. The server additionally checks the Moodle user's capabilities for each tool. After installing or updating MCP tools, reconnect the client to refresh its available tool definitions.

Connect in five steps

  1. Prepare Moodle. Install local_mcp, complete the upgrade, configure a publicly reachable HTTPS $CFG->wwwroot, enable Dynamic Client Registration (DCR) in plugin settings and test OAuth discovery as shown below. Consent requires a site administrator with moodle/site:config.
  2. Copy the server URL. Open Moodle MCP administration at /local/mcp/admin/connections.php and copy the displayed URL. It should look like https://YOUR-MOODLE/local/mcp/server.php, including any Moodle subdirectory, without token parameters.
  3. Register in ChatGPT. At chatgpt.com, open Plugins and add a custom MCP server. Enter a name such as Moodle MCP, optional description and PNG icon, select Server URL (not Tunnel), paste the URL and choose OAuth with automatic discovery and DCR. UI wording may change over time.
  4. Authorize access. Review the security warning, finish creating the plugin and sign in to Moodle when prompted. Check the application and scopes: mcp:read permits queries; mcp:write permits requesting changes, still subject to Moodle permissions and WRITE confirmation.
  5. Test and refresh. In a chat using the plugin, ask: “List the courses I can view in this Moodle.” If new providers or tools are installed, refresh the ChatGPT connection to reload tools/list.

Configure OAuth discovery

ChatGPT must be able to request https://YOUR-MOODLE/.well-known/oauth-authorization-server/local/mcp and receive JSON metadata. The plugin cannot register this root-level route itself: add the appropriate web-server rewrite, adapting paths if Moodle is installed in a subdirectory.

Apache:

RewriteRule ^\.well-known/oauth-authorization-server/local/mcp$ local/mcp/.well-known/oauth-authorization-server.php [L]

Nginx:

location = /.well-known/oauth-authorization-server/local/mcp {
    rewrite ^ /local/mcp/.well-known/oauth-authorization-server.php last;
}

See the OAuth discovery guide and the complete web-server configuration.

Common issues

  • OAuth discovery failed / 404: verify the rewrite, HTTPS, $CFG->wwwroot and the discovery URL's JSON response.
  • Client registration rejected: enable DCR in Moodle MCP settings.
  • 401 without authentication: the MCP endpoint requires an OAuth bearer token; that status is expected before authorization. Never use ?token=.
  • 403 or missing tools: check READ/WRITE scopes and Moodle user capabilities; OAuth cannot expand permissions.
  • New tools not listed: complete the Moodle upgrade, purge caches and refresh the ChatGPT connection.
For OAuth to work, serve Moodle over HTTPS, enable dynamic client registration and configure the web-server rewrite for /.well-known/oauth-authorization-server/local/mcp.
