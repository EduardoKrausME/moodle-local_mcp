Automatic MCP extensions

Moodle plugins can contribute their own MCP tools without modifying the central server or mixing READ and WRITE registries.

How it works

Add classes/mcp/provider.php to your plugin and implement local_mcp\extension\read_provider_interface, write_provider_interface or both. Methods get_read_tools() and get_write_tools() return tools implementing the corresponding READ and WRITE interfaces.

During tools/list, local_mcp uses Moodle component discovery to find providers belonging to installed and enabled plugins. Subplugins under local/mcp/tool also work through the mcptool plugin type, and older lib.php callback providers remain supported.

Choose globally unique tool names, preferably prefixed by your plugin component, and check Moodle capability and context in each tool. The server preserves scopes, limits, WRITE confirmation and audit for extension tools. Refresh your MCP client after installation or upgrades.

Being discovered does not give an extension permission to perform arbitrary actions: Moodle capabilities and MCP scopes still apply.
