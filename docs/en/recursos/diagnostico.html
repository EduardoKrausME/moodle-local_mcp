Diagnostics and auditing

Understand Moodle's state and debug integration failures using core site checks and logs that deliberately avoid sensitive information.

How it works

The READ tool get_site_status uses Moodle core checks and supports performance, status and security types. get_site_config compares stored and effective values to reveal config.php overrides. Approved configuration changes are applied through set_site_config.

The plugin writes significant lifecycle events to PHP error_log, prefixed with [local_mcp] and a 12-character request correlation identifier. Those records help trace requests, discovery, tool calls, permission denials, previews and errors without logging authorization headers, full argument values or Base64 images.

The audit trail records operation metadata while READ/WRITE/OAuth rate limits and permissions remain separate. If recently added tools are missing, update the plugin in Moodle, clear the relevant caches and reconnect the MCP client.

Never include access tokens or ?toke= URLs in diagnostic reports. Configure Nginx and Apache access logs to omit query strings for MCP endpoints.
