Privacy Policy

How Moodle MCP handles authentication, connection data, audit records and diagnostics.

Last updated: October 12, 2026

This policy describes the plugin hosted by each institution and the public documentation. It does not replace the privacy policy of any Moodle operator.

1. Scope and responsibilities

local_mcp is an open-source plugin installed on each organization's Moodle infrastructure. The organization operating Moodle determines processing purposes, permissions, lawful bases and responses to data subject requests under applicable law. The project maintainer publishes the source code; installation does not automatically transfer institution-hosted data to the maintainer. This policy does not cover any future separately hosted gateway or centralized service, which will need its own disclosures.

2. Data processed

The plugin processes internal user, OAuth client and connection IDs, registered redirect URLs, authorized scopes, creation and last-use times, IP addresses and technical authentication information. Depending on enabled tools and granted capabilities, MCP calls may read or change Moodle information such as courses, participants, activities, grades, reports and data exposed by other Moodle plugins.

3. Purposes of processing

This information supports connection authentication, authorization and revocation, READ/WRITE scope and Moodle capability checks, requested tool execution, write confirmation, troubleshooting and security audit records. Each organization must assess the purposes and lawful bases for making educational information available to an MCP client.

4. Authentication and security

Remote authorization uses OAuth Authorization Code with PKCE S256. Authorization codes, access tokens, refresh tokens and confirmation tokens are stored as hashes rather than complete secrets. Expiration times and scopes are managed by the server, and revoking a connection invalidates related credentials. OAuth authorization is not necessarily legal consent for every later processing activity.

5. Auditing and logs

Audit records may include user, client and connection IDs, tool and operation names, context, IP, timestamp, duration, status and summarized metadata. They are not designed to retain full ChatGPT conversations or complete tool arguments and results. Technical events are sent to the PHP error_log. Detailed JSON-RPC request and response logging is enabled by default in the current plugin configuration. Although known secrets and binary data are masked, these logs may contain personal information from Moodle records. Administrators should disable detailed logging after troubleshooting, restrict access and set PHP and HTTP server log retention policies.

6. Sharing and third-party services

When a tool runs, the required arguments and authorized results are transferred between the Moodle installation and its connected MCP client. If that client is ChatGPT, OpenAI may process data under its own terms and privacy policy; other clients and integrated plugins have their own practices. The organization must assess enabled tools, third parties and any data transfers. This document does not replace the policies of those services.

7. Storage and retention

Connection records, credential hashes and audit entries are stored in the institution's Moodle database. Audit retention defaults to 180 days and is administrator-configurable. A scheduled task removes old audit records and expired or used credentials when Moodle's task scheduler runs. Revocation does not immediately erase every historical record. Server logs, backups and content retained by an MCP client may have separate retention periods.

8. Data subject rights and deletion

Requests for access, correction, deletion and other applicable rights should go to the institution operating the Moodle installation. local_mcp integrates with Moodle's privacy API to export user-linked connection and audit data. Its privacy API deletion method removes audit records, not all connections, educational data, server logs or externally processed copies. Revoking OAuth access is a separate operation. The institution must perform additional steps when legally required.

9. Documentation site privacy

This documentation uses your browser's preferred language to select Portuguese or English. The light/dark theme preference is stored locally in the browser as mcp-theme. The hosting provider and its infrastructure may maintain technical access logs under their respective privacy policies.

10. Contact and updates

For information in a specific Moodle installation, contact that institution's Moodle administrator or privacy officer. For technical corrections about this project or page, use the maintainer contact page or the GitHub repository. This policy may be revised as the code and integrations change. The date above identifies the last update to this text.
