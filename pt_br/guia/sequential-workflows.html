Fluxos sequenciais com confirmação

Operações WRITE conduzidas etapa por etapa.

O servidor MCP pode planejar de 2 a 30 operações WRITE no mesmo curso e orientar o cliente por uma confirmação de cada vez. Esse comportamento é oferecido pelas instruções de descoberta do plugin Moodle e por um botão Próximo opcional no MCP Apps, não pela memória do ChatGPT nem por instruções personalizadas do usuário.

Como utilizar

  1. Chame workflow_sequence com action=start, courseid e uma lista ordenada de items, contendo somente o title e o nome da ferramenta WRITE em tool.
  2. A resposta fornece um workflow.id opaco e a primeira etapa. Prepare argumentos somente para essa etapa e chame a ferramenta original, informando workflow_id e workflow_step=1.
  3. Apresente a prévia e obtenha aprovação explícita do usuário. Repita a mesma ferramenta com argumentos idênticos e o confirmation_token. O plugin recusa etapas diferentes da atual e impede execuções paralelas.
  4. Confira o conteúdo criado com a ferramenta READ correspondente, quando disponível. O WRITE bem-sucedido devolve o progresso do fluxo e, em clientes compatíveis, um MCP App com botão Próximo. Clicar nesse botão apenas envia uma continuação da conversa; não autoriza automaticamente uma operação WRITE.
  5. Na etapa seguinte, chame workflow_sequence com action=next, courseid e workflow_id. Prepare outra prévia, aguarde aprovação e repita o procedimento. Use action=status para retomar ou action=cancel para descartar o planejamento.

Exemplo

{
  "action": "start",
  "courseid": 123,
  "items": [
    {"title": "Fórum de discussão", "tool": "forum_create_activity"},
    {"title": "Tarefa", "tool": "assign_create_activity"}
  ]
}

As ferramentas selecionadas precisam estar instaladas e publicadas pelo Moodle conectado; os nomes acima servem apenas como exemplo. O planejamento armazena somente nomes das ferramentas e rótulos, não HTML, argumentos, dados de estudantes ou tokens de confirmação.

Segurança e interoperabilidade

O mesmo usuário, cliente e conexão OAuth precisam acessar o fluxo. Em cada WRITE, o plugin confere a ferramenta, o número da etapa, o contexto do curso e as capacidades do Moodle. Uma operação aprovada reivindica sua etapa antes da execução; uma segunda chamada não consegue reivindicar a mesma etapa.

Se ocorrer falha, a etapa permanece propositalmente no estado executing, evitando a repetição automática de uma operação que talvez tenha sido parcialmente concluída no Moodle. Nesse caso, examine o curso e, se necessário, cancele o fluxo e planeje novamente.

Os fluxos expiram em sete dias. Seu estado é armazenado pela API config_plugins do Moodle.

Clientes compatíveis com MCP Apps acessam ui://local-mcp/workflow-next via resources/read e apresentam o botão Próximo depois de um WRITE rastreado. Clientes sem suporte de interface continuam recebendo dados estruturados e precisam oferecer uma continuação textual. O botão depende do suporte do cliente à extensão; o servidor não consegue impor um botão nativo no ChatGPT.

Operações fora do fluxo continuam funcionando como antes. O plugin não deduz automaticamente uma sequência de comandos a partir de texto livre: o cliente deve chamar explicitamente workflow_sequence(action=start) para ativar um plano controlado pelo servidor.
