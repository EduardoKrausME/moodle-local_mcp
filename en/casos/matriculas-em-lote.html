Enrol students from a spreadsheet into Moodle with ChatGPT

Match spreadsheet rows to users and courses, avoid duplicates and execute approved enrolments.

Copy ready-to-use prompt ↓How it works ↓
Real-world situation

An administrator receives an enrolment spreadsheet covering several courses and wants to know who is already enrolled.

Before you start

Connect Moodle to ChatGPT or Claude with appropriate permissions. To create or change data, the connection needs WRITE access and the signed-in user must have the relevant Moodle capabilities. Connection guide →

Step by step

  1. Attach the sheet, resolve course and user identities and flag ambiguous matches rather than guessing IDs.
  2. Read course participants and separate existing enrolments from needed changes.
  3. Confirm the learner role and an existing manual enrolment instance, then prepare enrol_user per learner.
  4. Approve every preview and reconcile created enrolments against pending or unmatched rows.

Ready-to-use ChatGPT or Claude prompt

Copy the prompt, edit course names and attach relevant files. The assistant is asked to show its plan before writing to Moodle.

Example prompt
Read my spreadsheet with learner email and course code. Find each user and course in Moodle, flag errors and duplicates, and compare with existing enrolments. Do not make any changes yet. After approval, prepare enrol_user only for missing enrolments, using the learner role verified in this installation. Present official previews and await my approval for every operation. Finish with a reconciliation per course: already enrolled, newly enrolled and pending.

Tools used in this workflow

ChatGPT or Claude selects the tools exposed by the connected installation. These tool names exist in the plugin and are relevant to this example:

search_userssearch_coursesget_course_participantsenrol_userunenrol_user

View tool reference and parameters →

How to verify the result

Check the final participant list and assigned role for every affected course; do not assume that a sheet row is an executed enrolment.

Limitations and safeguards

enrol_user requires an existing manual enrolment instance and operates on one account per call. The core plugin does not provide a single atomic bulk-enrolment operation.

Protected WRITE operations show a preview and execute only after explicit confirmation. If the assistant cannot access a tool, it must report that limitation instead of claiming it published content.
