Design beautiful activities in ChatGPT and publish them to Moodle

Create structured HTML with goals, cards, examples and accessible reading, then publish it as a real course activity.

Copy ready-to-use prompt ↓How it works ↓
Real-world situation

A teacher wants to replace a wall of text with content that is easier to study and maintain.

Before you start

Connect Moodle to ChatGPT or Claude with appropriate permissions. To create or change data, the connection needs WRITE access and the signed-in user must have the relevant Moodle capabilities. Connection guide →

Step by step

  1. Define audience, topic, style and learning goals; request semantic HTML without scripts.
  2. Review the content and check contrast, mobile layout and external links before publishing.
  3. Find the course section and call page_create_activity; consider label_create_activity for section-level text.
  4. Approve the write, open the real activity and inspect which markup and styles Moodle preserved.

Ready-to-use ChatGPT or Claude prompt

Copy the prompt, edit course names and attach relevant files. The assistant is asked to show its plan before writing to Moodle.

Example prompt
Create an accessible training page about online safety with an introduction, objectives, four practical tips, a strong-vs-weak password comparison and reflection questions. Use semantic HTML, no JavaScript, good contrast and a responsive layout compatible with Moodle themes. Show me the HTML for review. After approval, publish it as a Page in the course section I choose using page_create_activity, request the official confirmation and return the actual Moodle link.

Tools used in this workflow

ChatGPT or Claude selects the tools exposed by the connected installation. These tool names exist in the plugin and are relevant to this example:

get_course_sectionspage_create_activitypage_get_contentpage_update_contentlabel_create_activity

View tool reference and parameters →

How to verify the result

Open the result on desktop and mobile; check headings, keyboard access, images and links, and verify the actual rendered page.

Limitations and safeguards

Moodle may strip unsupported classes, CSS attributes and HTML elements depending on the site's cleaning settings. Embedded JavaScript is not appropriate; exact visual fidelity cannot be guaranteed.

Protected WRITE operations show a preview and execute only after explicit confirmation. If the assistant cannot access a tool, it must report that limitation instead of claiming it published content.
