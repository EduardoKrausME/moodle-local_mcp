READ and WRITE tools

Reading is one thing.
Changing is another.

READ and WRITE operations have independent registries, scopes and rate limits. READ-only connections cannot access administrative WRITE tools.

For changes requiring confirmation, the first call returns a preview and token. Execution occurs only after explicit approval and a second call.

Two-step confirmation

AI proposes.
You approve.

The MCP server validates arguments, scope and Moodle permissions, provides a preview and issues a temporary confirmation token. No data is written during the preview.

The second call must use the same arguments and follow explicit user approval; the audit trail captures the outcome.

Security by design

Permissions, traceability
and practical limits.

An access token's scope never replaces Moodle permissions; each tool validates user, context and capability before running.

✓

Moodle capabilities

Tools call has_capability() for the relevant context.

⌁

Protected credentials

Access and confirmation secrets are stored as hashes, not plaintext.

◉

Connection revocation

Revoking a connection invalidates its related credentials and authorizations.

▤

Audit without secrets

Logs and audits retain useful metadata without tokens or complete request bodies.
