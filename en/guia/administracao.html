Administration and operations

MCP settings, connections, OAuth clients, audit, diagnostics and tools.

Dashboard and administration pages

local_mcp administration is registered in Moodle's plugin administration menu. Administrative pages require both moodle/site:config and local/mcp:manage at system context. Having a valid MCP connection does not grant these capabilities.

Operational settings

Plugin settings control access-token, refresh-token, authorization-code and confirmation expiry, dynamic client registration, MCP body logging, per-minute READ/WRITE/OAuth rate limits and audit retention. Code defaults: one-hour access token, 90-day refresh token, five-minute authorization code, 30-minute confirmation and 180-day audit retention. Always verify effective settings before changing production behavior.

Dynamic client registration defaults to enabled; JSON message tracing defaults to disabled. Do not enable complete request tracing routinely: even with secret redaction, MCP messages may contain personal data.

Authentication, scopes and discovery

The combined endpoint is /local/mcp/server.php, with standalone /local/mcp/read.php and /local/mcp/write.php; public plugin discovery is at /local/mcp/discovery.php. OAuth uses Authorization Code with PKCE S256 and optional dynamic client registration. Send tokens in the Authorization: Bearer header, never as URL query parameters.

mcp:read and mcp:write are independent: WRITE does not imply READ. Every tool also checks Moodle context and capabilities. WRITE previews never save data; execution requires an explicit, short-lived, single-use confirmation bound to the acting identity, connection and exact arguments.

Revoking a connection invalidates its access and refresh tokens, pending authorizations and unused confirmation tokens. See the OAuth discovery setup and ChatGPT connection guide.

Audit and diagnostics

The audit page filters by READ/WRITE mode, status, tool, user and ChatGPT clients, and exports selected metadata to CSV. It does not export raw tool arguments or complete MCP message bodies.

Additional PHP protocol diagnostics are disabled by default. For troubleshooting, administrators can set $CFG->local_mcp_debugger = true; in Moodle's config.php before setup to enable metadata-only events. JSON-RPC body tracing requires a separate setting and should only be enabled briefly, as best-effort redaction does not guarantee the removal of all personal data.

Use get_site_status and get_site_config for approved system checks and settings; set_site_config changes only allowlisted keys. Scheduled cleanup tasks maintain temporary MCP data.

Tool discovery and integrations

The core registers 39 READ and 33 WRITE tools, and additionally discovers mcptool_* subplugin tools and other installed Moodle provider integrations. Actual tool availability depends on installed components, user capabilities, scope and site configuration. The effective tools/list response is the operational source of truth.

See the core tool catalog, guides for the 13 bundled subplugins and the extension API. Additional integrations include Kopere BI, Helpdesk and Kopere Proctoring. External tools only appear when the corresponding plugins are installed and accessible.

After deploying code to Moodle, run the plugin upgrade, purge caches when needed and refresh MCP tool discovery. A GitHub commit alone does not change an installed Moodle server.
