READ and WRITE tools

Separate operations for reading and changing data, with native permission checks and a confirmation flow that keeps previews distinct from authorization.

How it works

The server.php endpoint lists both tool groups while preserving independent READ and WRITE registries. The read.php and write.php endpoints are available for integrations needing separate channels. Scopes mcp:read and mcp:write are independent: WRITE does not automatically grant READ.

READ tools include search_courses, get_course, get_course_contents, get_grades, get_site_status and get_site_config. WRITE tools include create_course, bulk_create_courses, enrol_user, set_course_image, set_site_config, purge_css_cache and purge_all_caches, plus tools supplied by extensions.

For changes requiring confirmation, the first call returns confirmation_required, a preview and a confirmation_token. Clients must present the preview and obtain explicit consent before repeating the same tool with unchanged arguments and the token; changing inputs invalidates approval.

MCP scopes, Moodle capabilities and user confirmation are separate safeguards; none is sufficient on its own to authorize a WRITE operation.
