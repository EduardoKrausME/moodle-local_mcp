OAuth and discovery

Connect ChatGPT, Claude and other MCP-compatible AI tools to Moodle with OAuth 2.1, PKCE S256 and authorization restricted by Moodle user permissions.

How it works

Enable Dynamic client registration in local_mcp settings, serve Moodle over HTTPS and add /local/mcp/server.php to your client. Authentication and consent occur inside Moodle and authorization requires an administrator with moodle/site:config.

The OAuth issuer is https://YOUR-MOODLE/local/mcp. For automatic metadata discovery, configure a web-server rewrite mapping /.well-known/oauth-authorization-server/local/mcp to /local/mcp/.well-known/oauth-authorization-server.php. If Moodle is installed in a subdirectory, update both paths.

Clients must provide a resource parameter exactly matching the chosen MCP endpoint during authorization and token exchange. Access tokens are short-lived, refresh tokens rotate and revoking a connection invalidates the associated credentials.

The plugin cannot install a site-root .well-known rewrite by itself. Without it, OAuth discovery can fail even when the MCP endpoint is reachable.
